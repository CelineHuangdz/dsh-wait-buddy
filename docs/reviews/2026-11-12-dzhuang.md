## 背景确认

0.10.0 已内置前四轮反馈的修复：14px 小格子、BFS 点击寻路（90ms/步、路径绿点、目标靶环、不可达红叉）、带阴影眼睛的玩家头像。本轮反馈基于 0.10.0 实际体验（已重启插件 / 刷新后仍有下列问题）。

---

## P0 — 玩家小人太小，等于看不见

**现象**：感觉"没有小人"，点击后不知道角色在哪。

**根因**：`SF_CELL_TARGET = 14` 的格子里，头像半径 `r = max(unit * 0.28, 5)` ≈ 5px（L3336）。代码注释自己写了 "a speck avatar reads as 'no reaction'"，而 14px 格恰恰命中这个 speck 分支。

**建议**：
1. 头像放大到 `max(cell * 0.55, 8)`，允许略跨出格子边界。
2. 格间移动改为**平滑插值**（90ms 一跳 → 两格间过渡动画），加朝向（眼睛随行走方向偏移）与 2 帧走路摆动。

## P0 — 精灵造型太丑：全是"带眼睛的椭圆"

**现象**：54 种精灵观感全是圆的，差异仅椭圆长宽比。

**根因**：`drawSfSprite`（L3358）三种体型（round/block/tall）只调 `rx`/`ry` 两个系数，无任何附加特征。

**建议**（维持"无外部素材、纯 Canvas"约束）：
1. 每种体型叠加**外部特征**：耳朵 / 尾巴 / 角 / 小短腿，用 2~3 个形状组合出剪影差异。
2. 加高光渐变 + 深色描边；稀有度可视化（珍稀加光环 / 粒子）。
3. 遇怪立绘加入场弹跳 + 上下浮动 idle 动画。

## P1 — 地形像"撒芝麻"，不像地图

**现象**：水面 / 岩石随机单格散布，噪点感强、丑。

**根因**：`sfMapOf`（L2864）逐格独立掷骰（i.i.d.），无空间相关性。

**建议**：用值噪声或**元胞自动机平滑**（2~3 轮多数邻域投票）生成连片湖泊与岩石群；保持确定性种子（现有 `region × cols × rows` 种子可沿用）。

## P1 — 自动寻路途中遇怪太突兀

**现象**：点击远处目标后角色自己走，中途突然弹遇怪窗，"过会又弹出来遇到精灵"，没有铺垫。

**建议**：遇怪前先在当前格播放 ~300ms 草丛抖动 + 感叹号，再弹窗。

## P2 — 细节体验

1. 不可达红叉闪烁 450ms（L3088）偏短，建议 800ms 或加轻微震动反馈。
2. 图鉴目前是纯文字列表（L3483），建议改为迷你 canvas 头像网格（`drawSfSprite` 可直接复用，参考 `SfPortrait` L3465）。

## 建议专题：游戏之外的功能与显示改进（P1/P2，全景梳理）

抓精灵之外，对插件其余部分（监控看板 / 胶囊 / 浮动小窗 / 其他游戏 / 通知）的体验建议：

### 监控看板（核心职能，建议 P1）

1. **耗时与进度可视化**：状态行已有"N 步 · M:SS"，建议加一条**细进度/活动脉冲条**（如最近 60 秒有无工具活动的 sparkline），一眼区分"卡住了"和"在正常跑"——现在长时间无输出时无法判断是否死循环。
2. **活动流过滤**：活动流全是命令/工具行时很难扫；建议按工具名折叠同类连续项（如连续 10 次 Read 折成"Read ×10"），并支持点击复制命令全文。
3. **多会话概览**：胶囊只跟随主视图会话；看板里加一个**其他运行中会话的迷你列表**（状态点 + 名称 + 耗时，点击跳转），契合"离开工位前扫一眼全部任务"的场景。

### 胶囊与浮动小窗（P2）

4. **收起态摘要太挤**：状态色点 + 摘要文字在 92px 宽度下经常截断，建议可配置只显示色点（极简模式）。
5. **小窗游戏页签已三个**，320px 窄窗下页签行换行挤压棋盘（CHANGELOG 0.10.0 已为此砍棋盘到 128px）；建议页签超宽时收进"▾"下拉，把棋盘尺寸还回来。
6. **拖拽位置易丢**：`pillPos` 持久化了，但显示器分辨率变化后可能停在视口外；建议渲染时校验并拉回视口内（钳制逻辑已有，疑似只在拖动时生效）。

### 五子棋（P2）

7. **悔棋**：人机对弈没有悔棋，手滑点错只能重开；加"悔一步"按钮（撤销最后一对人机着子）成本很低。
8. **最后一手标记**：棋盘上标出电脑最后一手落点（现在要自己找）。

### 通知（P2）

9. **通知点击直达**：系统通知目前只有文案；点击通知若能跳到对应会话/看板，"后台等审批"闭环就完整了（若宿主 Notification 无点击事件则做不了，需负责人确认）。
10. **完成通知带结果摘要**：「成功 · N 步」之外附最后一条工具名或总 token 数，不点开也能粗判这轮干了什么。

### 显示细节（P2）

11. **浅色主题适配**：游戏区大量硬编码深色（`#141f2e` 等），宿主切浅色主题时游戏区仍是一块深色补丁；至少给边框/文字用主题令牌过渡。
12. **`prefers-reduced-motion` 覆盖不全**：D43 只关了脉冲/浮字/toast，游戏区动画（蛇移动、精灵 idle）未纳入。
13. **键盘可达性**：抓精灵 `keyboard: false`，五子棋/贪吃蛇的键盘操作也没有 focus 指示环；无鼠标场景（平板）基本不可玩，可作远期项。

## 建议专题：整体改走像素风（P1，设计方向提案）

**动机**：插件客户端无法引入素材文件和游戏引擎，当前"用 Canvas 画平滑矢量图形模仿精致游戏"的路子已经到头了（巨格地形、椭圆精灵都证明费力不讨好）。像素风恰好相反——**它以约束为美**，纯 Canvas `fillRect` 画 4×4 像素块即可，零素材、零引擎，而且"简单但有意思"正是像素游戏的公认气质。具体做法：

1. **离屏精灵 + 整数缩放**：每个精灵/头像先在离屏 canvas 上按 16×16 像素画好，再以整数倍放大绘制到主画布，`ctx.imageSmoothingEnabled = false` 锁定锐利边缘。一次建模，地图、遇怪立绘、图鉴三处复用。
2. **地形像素化**：草地 = 两三种绿色的 4px 抖动块；水面 = 两帧交替的像素波纹（全局 tick 翻帧即得廉价动画）；岩石 = 3~4 个灰色矩形叠出立体感；空地 = 深底色加稀疏单像素星点。不再画平滑渐变和弯草曲线。
3. **精灵造型重做（与 P0 造型问题合并解决）**：54 种 = 身体剪影（圆胖/细长/方壮，各配耳/尾/鳍/角中的一种）× 6 色板 × 3 花纹（纯色/斑纹条/肚皮色），每种先画 16×16 像素稿。像素风下"都是小方块生物"反而可爱，不再有"椭圆带眼睛"的廉价感。
4. **玩家小人**：8×12 像素小人（帽子 + 身体 + 两帧走路腿交替），比圆形头像辨识度高一个量级，直接解决"看不到小人"。
5. **UI 同步像素化**：遇怪弹窗、图鉴、按钮用像素边框（box-shadow 拼直角）+ 等宽/像素字体；`image-rendering: pixelated` 全局声明。
6. **动效从简**：遇怪 = 精灵入场两帧闪烁 + 抖动；捕获成功 = 精灵缩进精灵球图案 + 星形像素闪光。像素风的两帧动画就足够生动，不需要平滑插值。

**低成本替代方案**（若不想全面改风格）：至少把现有绘制里的平滑渐变全部换成**扁平色块 + 1px 深色描边**，观感立刻统一；这是 30 分钟级的改动。

## 建议专题：玩法层低成本增强（P2，供选做）

像素风改造之外，逻辑层还有几个便宜的乐趣增量：

1. **连踩草地缓冲**：自动寻路途中遇怪目前的"突兀感"，除草丛抖动预警外，可让本次行走路径上已踩过的草短暂降低遇怪率（防连续脸黑）。
2. **图鉴奖励钩子**：收集满一个色系（6 只）给一条 congratulation 文案 + 图鉴页签高亮；全收集给特殊 region。纯逻辑，几十行。
3. **区域主题化**：`nextRegion` 时按 region 编号切换地形色板（雪原/沙漠/火山配色），复用同一套绘制代码，只换颜色表——地图重复感立刻消失。
4. **捕获概率展示**：遇怪弹窗标注"捕获率 70%/45%/20%"，玩家有预期才不会觉得"球总是丢空"。
5. **音效（可选）**：WebAudio 简单振荡器即可产出 8-bit 风格哔哔声（移动/遇怪/捕获三枚），无需素材文件；默认关闭、设置项开启。

## P0（新增，2026-11-12 截图实证）— `fitBoard` 未生效，棋盘仍是 24×12 巨格

**现象**（完整视图实截图）：棋盘铺满 ~1580px 宽的游戏区，但仍按初始 `cols=24, rows=12` 渲染，单格约 66px 见方——用户观感"格子太大太丑"；玩家头像在巨格里比例过小且难以辨认，"完全看不到"。

**根因分析**：`sfFitDims`（L2889）按 `SF_CELL_TARGET=14` 本应把该棋盘拟合成 ~90×44 格，但实际没有发生。`fitBoard`（L3100）有两个提前返回分支：`encounter !== null` 或 `path.length > 0` 时直接跳过；且 `measure()` 在 rect ≤ 60px 时静默放弃、无重试。**疑似：在 fitBoard 生效前发生过任意移动或遇怪，棋盘将永久停在 24×12 巨格状态**。修复建议：
1. 跳过条件只保留 `path.length > 0`；遇怪时允许重拟合（或遇怪结束后补一次 fit）；
2. `measure` 中 rect 过小时用 rAF/timeout 安排重试，而非放弃；
3. 拟合会经 `sfSpawnOf` 重置出生点，若 `pos` 落在不可通行格需就近迁移，避免静默传送。

**注**：本条是"格子大、看不到小人"的直接主因；前两条 P0（头像放大、精灵造型）仍然成立，本条修复后 14px 格 + 放大头像的方案才能被真实验证。
