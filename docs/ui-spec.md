# WaitBuddy 界面规范（v13）

> 状态：**先于实现**，代码必须与本文件一致；任何界面变更先改本文件，再改 `client.js`。
> 适用范围：`conversation.view` 中的 WaitBuddy 视图（M1 监控 + M2 游戏），以及 §8 低调模式的表面（完整视图 + 全局胶囊；状态点 / 侧栏面板已按 D31/D32 移除）。
> 基线：[M0 定稿](baseline-m0.md) · 对照：[M0 对照与偏差](m0-compliance.md)

## 1. 设计原则

1. **监控优先**：告警 > 状态 / 活动流 > 游戏。告警永远在最上方，且不依赖滚动可见。
2. **上下分区、整宽铺满**：状态区在上、游戏区在下，两个区都占满会话视图宽度；不设 `max-width` 居中窄栏，也不做左右分栏。
2b. **棋盘吃满横向空间**：宽度 100%、高度**弹性填充**（基准 `min(46vh,480px)`，下限 200px、上限 520px），格数按实测尺寸推导（约 18px 一格），同一高度下尽量多列，保证铺满且格子仍是正方形（决策 D11/D12/D19）。
3. **一层表面**：一屏内只允许一个"实体表面"——游戏棋盘。其余信息用排版和发丝线组织，不套卡片。
4. **跟随宿主**：只使用 `cordis_inspect_query` `Theme` 列出的 `--dsw-alias-*` 令牌；字号、间距、圆角向宿主看齐（10/11/12/13/15，4px 栅格，圆角 8/12/14）。
5. **不做假进度**：只显示真实发生的「已完成 N 步」，不显示总步数、不显示百分比；活动流只补充"命令 / 工具调用"，不展示模型推理原文（M0 §6、D1、D27）。

## 2. 布局（上下两段，整宽）

```
┌ 容器：width 100%，padding 10/24/56，无 max-width ─────────────────────────────┐
│ [告警条（仅高告警时，整宽，可换行；吸顶）]                                     │
│                                                                           │
│ ● 任务执行成功 ✅                │ 工具  read_file client.js                   │
│ 更新于 20:23:58 · 已完成 8 步    │ 命令  sed -n '1,120p' client.js            │
│ 仅跟踪当前会话 · 游戏与任务独立   │ 工具  plugin_manager set_plugin            │
│ ───────────────────────────────────────────────────────────── 发丝线        │
│                                                                           │
│ ┌────────────────────────────────────────────────────────────────────┐    │
│ │              棋盘（贪吃蛇：自适应网格 / 五子棋：方形居中）              │    │
│ └────────────────────────────────────────────────────────────────────┘    │
│ 贪吃蛇 · 得分 0 · 最高 0                  [重置]          方向键控制，点棋盘后生效 │
└───────────────────────────────────────────────────────────────────────────┘
```

- 状态区：`display:flex; gap:24px; flex-wrap:wrap`，下方一条发丝线。
  - 左列 `flex:0 0 auto; min-width:260px`：状态行（点 + 15px 文案）、更新时间 + 已完成步数、免责说明（10px，可换行）。
  - 右列 `flex:1 1 420px`：活动流，最多 3 条，每条 `kind` + 文本（单行省略）。
- 游戏区：棋盘 `width:100%`，高度**弹性填充**剩余空间（`flex:1`，基准 `min(46vh,480px)`，下限 200px、上限 520px），下方一行说明（游戏切换 / 设置 / 数据 / 操作 / 提示）。
- 游戏切换：说明行最左是两个轻量页签「贪吃蛇 / 五子棋」，同一时间只渲染一个棋盘；切换不重置任何一局。
- 棋盘尺寸变化时（窗口缩放）重新推导格数，格子仍为正方形；对局进行中不改变格数，避免蛇出界。
- 一屏高度预算（约 650px 视口）：状态区 ≈ 66 + 说明行 ≈ 32 + 间距/内边距 ≈ 90，其余全部给棋盘（约 260–420px，随窗口高度变化）；告警出现时棋盘自动收缩，仍不滚动。
- 告警条位于 `.wb-inner` 滚动容器之外，作为独立注意力层常驻可见；`.wb-root` 使用 flex column，`.wb-inner` 滚动，告警出现时只压缩内容区，不随内容滚走。
- 顶部内边距 10px（窄窗 8px），让状态行贴近视图顶部；底部内边距 **176px**（窄窗同），为宿主 Todo dock 的**展开态**（标题行 + 用量/进度行，实测约 150px + 边距）让出空间——2026-11-10 修订：原 56px/窄窗 100px 是按 dock 收起态（38px）估的，真机展开态会把游戏控制行整个盖住；320px 下棋盘固定 128px（0.10.0 由 140px 再缩：第四款页签使控制行多换一行，flex 子元素会溢进滚动容器 padding 区，加大 padding 无效——D40 教训）、隐藏页脚免责声明行，保证内容在窄窗内放得下且控制行滚到底也不被 dock 覆盖；Todo dock 属于宿主并会覆盖视图底部，插件不改它的外边距，只能用更大的底部留白让出空间。视觉回归的宿主 dock mock 同步为 150px 展开态，断言改为"滚到底后控制行不被覆盖"。
- 切视图 / 切会话 / 页面恢复可见时，`.wb-inner` 的 `scrollTop` 归零，保证告警和状态行重新出现在顶部。

## 3. 活动流（补充步数）

## 5. 状态与文案

| 状态 | 状态文本 | 更新时间 |
|---|---|---|
| idle | 空闲 · 等待本会话任务 | 有则显示 |
| running（无活动） | 任务开始，Agent 正在规划 | 显示 |
| running（有活动） | 正在执行任务 | 显示 |
| pending_approval | 【重要】等待你审批工具调用！ | 显示 |
| success | 任务执行成功 ✅ | 显示 |
| failed | 任务执行失败 | 显示 |
| aborted | 任务已中断（未知结束原因时显示「本轮已结束（未知原因）」） | 显示 |
| loading（health） | 正在读取监控数据… | — |
| degraded（health） | 监控数据不可用 | — |
| stale（health） | 状态同步中断（可能已断开） | — |

- 显示真实 `stepCount`（「已完成 N 步」），不显示总步数；步数为 0 时省略。
- `health` 是 Client 展示字段，不改变 M0 的六值 `status`；approval / failed 的告警文案优先于 health。
- **失败原因按原因码翻译**（D41，0.7.0）：Host 投影携带 `reasonCode`（`error` / `max-tokens` / `blocked` / … / `unknown`），Client 查词典显示「模型请求失败 / 本轮达到模型输出上限 / 本轮被阻止，未继续执行」；`errorMessage` 只保留上游原文，作为告警条次要细节（悬停 title）显示，**投影内不写插件文案**。
- 告警条：可换行，`【重要】等待你审批工具调用 · 工具 xxx` / `任务执行失败 · <按原因码翻译的文案>`；不提供任何操作按钮。

### 5.1 任务结束后的「查看对话」入口

- 仅在本轮结束（`success` / `failed` / `aborted`）时，状态行右侧出现一个次级按钮 **「查看对话」**；运行中、空闲时不显示。
- 点击调用 Conversation 视图的 `openView('chat', '')` 切回「对话」标签，只做视图导航：不发送消息、不取消/重试任务、不触碰审批。
- 若宿主未提供 `openView`（能力缺失），按钮不渲染，降级为纯看板。

## 6. 棋盘与游戏操作

### 6.0 游戏切换

- 说明行左侧「贪吃蛇」「五子棋」两个轻量页签，选中态用描边 + 背景区分；切换时**两局都保留**（切到五子棋会自动暂停贪吃蛇）。
- 两个游戏共用同一个棋盘容器与同一行说明；同一时刻只渲染一个画布。

### 6.0.1 游戏设置

- 可点击项一律渲染成**分段控件**（`.wb-seg`：外描边 + 内分隔线的胶囊），不可交互的文字（如「速度」「难度」）是**无边框的纯文本标签**，两者在视觉上必须能一眼区分（决策 D18）。
- 说明行在页签右侧提供当前游戏的设置：
  - 贪吃蛇：`速度` 三档「慢 / 标准 / 快」，决定本局起始节奏与加速步长。
  - 五子棋：`难度` 三档「初级 / 中级 / 高级」，决定电脑的候选范围、防守权重与随机度。
- 设置改动立即保存到浏览器本地存储（键 `dsh-wait-buddy.settings.v1`），刷新后保留；不影响监控数据，也不涉及分数持久化。
- 切换设置在界面上即时生效：贪吃蛇改速度会同时调整当前局节奏；五子棋改难度作用于下一手电脑落子。

### 6.1 贪吃蛇

- 棋盘尺寸由容器实测：`cols = clamp(round(width / 18), 16, 120)`、`rows = max(round(height / 18), 8)`；绘制时 `cellW = width/cols`、`cellH = height/rows`，格子近似正方形。
- 格数在**每局开始时锁定**：resize 只在外层容器变化且当前不是 running/paused 时重新推导；对局中窗口缩放仅拉伸绘制，不改格数。
- 初始蛇 3 节居中，食物随机落在空格。
- 不提供软方向键（决策 D7）。**注意：M0 §5 要求画布内软按钮，D7 与基线冲突，待产品负责人确认；确认前 M1 验收按已知偏离记录。**
- 方向键仅在焦点位于视图内时生效：视图根节点与棋盘容器均为 `tabIndex=0`，点击棋盘即可获得焦点；点击「开始/继续/再来一局」后自动把焦点交还视图。
- 保留「重置」按钮与浮层主按钮；**不设「暂停/继续」按钮（D35）**——空格暂停/继续，点击棋盘（暂停浮层）也可恢复。
- 提示文案固定为「方向键控制，点棋盘后生效」。
- 取舍：触屏或纯鼠标设备无法操控方向，明确接受。

### 6.2 五子棋

- 15×15 交叉点；人执黑先手、电脑执白。电脑为纯前端启发式：先确保自己连五、再堵对方连五，否则按四方向的连子数/开口数加权选点，候选限定在已有棋子周围 2 格内。
- 棋盘为正方面板，边长 = 画布可用高度（上限 520px），水平居中，木质底色 + 网格 + 星位，最后一手用红点标记。
- 交互：点击交叉点落子；连五或满盘时棋盘上浮层显示结果与「再来一局」。
- 说明行：`你 N 手 · 电脑 M 手` +「重新开始」+ 提示「点击交叉点落子」。
- 难度三档：初级（候选半径 1、防守权重 0.35、前 3 点随机）、中级（半径 2、防守 0.9、取最优）、高级（半径 3、防守 1.15、最优并偏好制造双威胁，**且会提前封堵对手的成四点与双三叉点**）。三档都会堵对方成五，强弱来自候选范围、防守权重、随机度与高级档的主要威胁封堵。
- 不做悔棋、计时、联网（后续迭代）。

### 6.3 M3 联动反馈

- `agent:approval_enter`：贪吃蛇 running 时自动暂停，浮层标题「等待审批」、正文「Agent 等待审批，已自动暂停」；浮层无恢复按钮（D35）。
- `agent:approval_leave`：不自动恢复；浮层正文「已处理，按空格或点击继续」，用户点击暂停浮层或按空格恢复。
- `agent:step_advance`：+5 分，棋盘中央浮字 `+5`，约 1.2 秒淡出，不打断游玩。
- `agent:task_finish` success：+50 分，棋盘顶部 toast「任务完成！+50 分」，约 4 秒淡出。
- `agent:task_finish` failed / aborted：只显示「任务失败」/「任务已中断」toast，不重置、不结束本局；未知原因显示「本轮已结束」。
- 奖励只在游戏非 idle 时生效；奖励不改变 `tickMs`。
- 五子棋不消费暂停/奖励信号（M3 预设只作用于贪吃蛇）。

### 6.4 探索抓精灵（D47，0.10.0）

- 地图：12×12 地形格（草地/空地/水域/岩石）；水与岩石不可通行；点击**相邻**可通行格移动（可行进的相邻格高亮）；出生点为地图中心，保证可通行。「换区域」按区域号重生成地图（确定性种子）。
- 遇怪：移动到草地格时 35% 概率遇怪；稀有度先滚动（珍稀 5% / 稀有 25% / 常见 70%），再在该稀有度内均匀取一种精灵。
- 捕获：单击「精灵球」——常见 70% / 稀有 45% / 珍稀 20%；成功入图鉴（同种可重复，计数累加），失败即逃跑；「放过」直接结束本次遇怪。
- 精灵：体型（圆/方/长）× 配色（6 色）× 花纹（素/点/纹）= 54 种，程序化 Canvas 绘制；名字由词典部件合成；稀有度由编号确定（珍稀 6 / 稀有 12 / 常见 36）。
- 图鉴：`localStorage` → `dsh-wait-buddy.dex.v1`（`{caught:{id:count}}`）；状态行显示「图鉴 N/54」，点开浮层列出已收集（名字 × 数量）；跨刷新、跨会话保留。
- 联动：无（回合制、无 tick；Agent 信号仍只驱动贪吃蛇）。

## 7. 浮层与可访问性

- 贪吃蛇浮层（D35：暂停类浮层无按钮，点击浮层或空格恢复）：idle「方向键控制，吃到果实得分」→ 开始游戏；paused「已暂停」；manual「已手动暂停，点击继续恢复」；session-switch「切换会话后已暂停」；view-inactive「视图切换后已暂停」；approval「等待审批」（点击不恢复），且优先于「游戏结束」/「开始游戏」浮层；approval 消失后「已处理，按空格或点击继续」；over「游戏结束 + 得分 N」→ 再来一局。浮层不重复游戏标题。
- 暂停浮层使用半透明遮罩（约 48%），保留棋盘/蛇的可辨识度，避免用户误以为进度丢失。
- 五子棋浮层：won「你赢了」/ lost「电脑赢了」/ draw「平局」→ 再来一局（仅终局出现）。
- 棋盘 `role="img"` + `aria-label`（含当前得分）；状态文本 `aria-live="polite"`；告警 `role="alert"`；按钮均有可读标签。
- 视图切走 / 切会话 / 页面隐藏 → 自动暂停并保留进度。

### 8.4 全局胶囊与浮动小窗（L2，P3 → D30 修订，已实现）

- 收起态：单行胶囊「● 状态 · N 步 · M:SS」，摘要按状态补全（D33）——运行中「N 步 · M:SS」、待审批「待审批」（按 pendingKind 区分）、成功「成功 · N 步」、失败「失败」、中断「已中断」、空闲「空闲」；初始按 `pillCorner` 停在右上（默认）/右下/左上；**点击任意处直接展开成浮动小窗**（不打开右侧栏）；**按住即可拖动**（移动超过 4px 视为拖动并抑制点击），位置与展开态共用并持久化到 `pillPos`。胶囊层由宿主 `shell.overlay` 提供、层本身点击穿透，仅胶囊接收指针事件。
- **展开态 = 可拖拽浮动小窗（D30）**：约 300px 宽，承载整个 WaitBuddy——
  - 头部：拖拽柄（按下拖动整窗）+ 状态点 + 摘要 + 最新一条活动（截断）+ 收起按钮；
  - 游戏区：贪吃蛇固定 32×12 格（约 296×112px），下方一行「得分 · 暂停 · 重置」；方向键 + 空格，点棋盘获焦（同 §6.1 焦点规则）；
  - 拖拽位置钳制在视口内，松手写入 `pillPos` 设置，刷新后原位恢复；收起不丢位置。
- **鼠标移出自动暂停（仅浮动小窗的贪吃蛇，2026-11-09 修订）**：指针离开小窗时若贪吃蛇运行中→自动暂停；回到小窗**不自动恢复**——须按空格或点击暂停浮层（与 M0 §9 手动恢复语义一致）。五子棋为回合制，不参与移出暂停。手动暂停、审批暂停、隐藏暂停同样走手动恢复。L4 完整视图不做鼠标暂停（键盘玩家鼠标常在棋盘外）。
- **游戏页签（D33，D34 修订为共用同一局）**：小窗游戏区提供「贪吃蛇 / 五子棋」两个页签，与完整视图（L4）**共用全局单局**——分数、棋面、暂停状态在两边实时同步；格数 idle 时按当前容器推导（运行中锁定只缩放）；五子棋正方小棋盘（约 184px）点击交叉点落子、难度沿用全局设置、终局浮层「再来一局」。
- 迷你局仍是独立轻量实例（不消费 `agent:*` 信号、不持久化分数）；仅贪吃蛇，五子棋不进小窗。
- 红线：浮窗初始位置在角落、可拖至任意处，z-index 低于宿主审批层；审批等待时只显示「待审批」、展开按钮禁用、游戏区收起；不遮挡、不拦截任何原生交互。

### 8.5 系统通知（L0）

- 触发条件：`document.hasFocus() === false` 且事件属于审批（`approval_enter`）/ 完成（`task_finish: success`）/ 失败（`task_finish: failed/aborted`）三类。
- 去重：复用 `signalHub` 的 `type + sessionId + key`，每个事件只通知一次；`step_advance` 不通知。
- 文案：不含命令、参数、活动流文本。模板：「WaitBuddy：会话 <名称> 等待审批」/「任务完成」/「任务失败」。与 D27 同理，屏幕共享时不泄露内容。
- 权限：**用户手势触发**（D42，0.7.0）——看板脚注「启用系统通知」按钮请求 `Notification`；插件加载时不再自动请求。权限未授予时通知静默不发；在 DSH 桌面版实测，被宿主拦截则本节整体退化为页面内提醒，其余级别不受影响。

### 8.6 一键隐藏

- 快捷键 `Ctrl/Cmd+Shift+W`，在 常规 ↔ 后台 之间切换（D31：状态点移除后为两态；D33：`quiet` 显示名「后台」）。
- 实现：window keydown 监听（输入框/文本域/可编辑区域内不触发）。宿主 `ctx.shortcuts.register` 是命令目录、只解析命令 id，无插件可用的动作绑定契约；契约核实后再迁移。
- **可关闭**（D42，0.7.0）：设置项 `shortcut`（默认开）；关闭后监听不拦截按键（不 preventDefault，浏览器/宿主的 Ctrl/Cmd+Shift+W 原生行为让位）。
- 进入隐藏：暂停游戏（`pauseReasons` 新增 `hidden` 原因）、L2 收起；退出隐藏：移除 `hidden` 暂停原因，游戏**保持暂停**（沿用「手动恢复」语义），浮层提示「已从隐藏中恢复，按空格或点击继续」。

### 8.7 设置

- 键沿用 `dsh-wait-buddy.settings.v1`（D17），新增字段，仅存本机：
  - `presence`：`quiet` / `pill`（默认 `pill`；显示名「后台 / 胶囊」，旧值 `dot` 回落到默认，D31/D33）。
  - `notify`：布尔（默认 `true`），控制 §8.5 系统通知总开关。
  - `shortcut`：布尔（默认 `true`，D42），控制 §8.6 快捷键。
  - `pillCorner`：`top-right` / `bottom-right` / `top-left`（默认 `top-right`，仅决定胶囊首次出现位置）。
  - `pillPos`：`{x,y}` 或 `null`（D30），胶囊/浮动小窗的拖拽位置。
- 设置入口：看板脚注行的「存在感」分段控件（后台/胶囊，D32/D33 两态）、「快捷键」分段控件（开/关，D42）；权限为 `default` 时脚注显示「启用系统通知」按钮（用户手势请求权限，D42）。`notify` 总开关暂无界面入口（localStorage 直改），后续按需补。
- **视图跳转失败的可见反馈**（D42，0.7.0）：后台按钮驱动的视图跳转（宿主无公开 API，见 compat.md）失败时，胶囊显示「无法自动切换视图，请手动点击 WaitBuddy 标签」4 秒；后台模式下若通知权限已授予，改发一条系统通知。
