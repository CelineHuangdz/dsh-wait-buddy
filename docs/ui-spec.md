# WaitBuddy 界面规范（v12）

> 状态：**先于实现**，代码必须与本文件一致；任何界面变更先改本文件，再改 `client.js`。
> 适用范围：`conversation.view` 中的 WaitBuddy 视图（M1 监控 + M2 游戏）。
> 基线：[M0 定稿](baseline-m0.md) · 对照：[M0 对照与偏差](m0-compliance.md)

## 1. 设计原则

1. **监控优先**：告警 > 状态 / 活动流 > 游戏。告警永远在最上方，且不依赖滚动可见。
2. **上下分区、整宽铺满**：状态区在上、游戏区在下，两个区都占满会话视图宽度；不设 `max-width` 居中窄栏，也不做左右分栏。
2b. **棋盘吃满横向空间**：宽度 100%、高度**弹性填充**（基准 `min(46vh,480px)`，下限 200px、上限 520px），格数按实测尺寸推导（约 18px 一格），同一高度下尽量多列，保证铺满且格子仍是正方形（决策 D11/D12/D19）。
3. **一层表面**：一屏内只允许一个"实体表面"——游戏棋盘。其余信息用排版和发丝线组织，不套卡片。
4. **跟随宿主**：只使用 `cordis_inspect_query` `Theme` 列出的 `--dsw-alias-*` 令牌；字号、间距、圆角向宿主看齐（10/11/12/13/15，4px 栅格，圆角 8/12/14）。
5. **不做假进度**：只显示真实发生的「已完成 N 步」，不显示总步数、不显示百分比；活动流只补充"命令 / 工具调用"，不展示模型推理原文（M0 §6、D1、D27）。

## 2. 布局（上下两段，整宽）

```
┌ 容器：width 100%，padding 10/24/56，无 max-width ─────────────────────────────┐
│ [告警条（仅高告警时，整宽，可换行；吸顶）]                                     │
│                                                                           │
│ ● 任务执行成功 ✅                │ 工具  read_file client.js                   │
│ 更新于 20:23:58 · 已完成 8 步    │ 命令  sed -n '1,120p' client.js            │
│ 仅跟踪当前会话 · 游戏与任务独立   │ 工具  plugin_manager set_plugin            │
│ ───────────────────────────────────────────────────────────── 发丝线        │
│                                                                           │
│ ┌────────────────────────────────────────────────────────────────────┐    │
│ │              棋盘（贪吃蛇：自适应网格 / 五子棋：方形居中）              │    │
│ └────────────────────────────────────────────────────────────────────┘    │
│ 贪吃蛇 · 得分 0 · 最高 0            [暂停] [重置]       方向键控制，点棋盘后生效 │
└───────────────────────────────────────────────────────────────────────────┘
```

- 状态区：`display:flex; gap:24px; flex-wrap:wrap`，下方一条发丝线。
  - 左列 `flex:0 0 auto; min-width:260px`：状态行（点 + 15px 文案）、更新时间 + 已完成步数、免责说明（10px，可换行）。
  - 右列 `flex:1 1 420px`：活动流，最多 3 条，每条 `kind` + 文本（单行省略）。
- 游戏区：棋盘 `width:100%`，高度**弹性填充**剩余空间（`flex:1`，基准 `min(46vh,480px)`，下限 200px、上限 520px），下方一行说明（游戏切换 / 设置 / 数据 / 操作 / 提示）。
- 游戏切换：说明行最左是两个轻量页签「贪吃蛇 / 五子棋」，同一时间只渲染一个棋盘；切换不重置任何一局。
- 棋盘尺寸变化时（窗口缩放）重新推导格数，格子仍为正方形；对局进行中不改变格数，避免蛇出界。
- 一屏高度预算（约 650px 视口）：状态区 ≈ 66 + 说明行 ≈ 32 + 间距/内边距 ≈ 90，其余全部给棋盘（约 260–420px，随窗口高度变化）；告警出现时棋盘自动收缩，仍不滚动。
- 告警条位于 `.wb-inner` 滚动容器之外，作为独立注意力层常驻可见；`.wb-root` 使用 flex column，`.wb-inner` 滚动，告警出现时只压缩内容区，不随内容滚走。
- 顶部内边距 10px（窄窗 8px），让状态行贴近视图顶部；底部内边距 56px；窄窗 100px；320px 下棋盘固定 190px，避开覆盖在视图底部的 composer，保证控制行可见，避免控制行与宿主 Todo dock 贴得太近；Todo dock 属于宿主并会覆盖视图底部，插件不改它的外边距，只能用更大的底部留白让出空间。
- 切视图 / 切会话 / 页面恢复可见时，`.wb-inner` 的 `scrollTop` 归零，保证告警和状态行重新出现在顶部。

## 3. 活动流（补充步数）

| kind | 来源事件 | 展示 |
|---|---|---|
| `command`（命令） | 携带 `command` 参数的 `tool/call`（bash 等） | 命令首行，截断到 120 字符 |
| `tool`（工具） | 其它 `tool/call` | `工具名 + 关键参数摘要`，截断到 120 字符 |

- 最多保留 3 条，最新在上；与上一条完全相同的不重复追加。
- 新一轮任务（`turn/start`）清空活动流。
- 活动流为空时，右列显示一行「等待 Agent 活动」。

## 4. 排版与令牌

| 元素 | 规格 | 令牌 |
|---|---|---|
| 状态文本 | 15px / 600 | `--dsw-alias-label-primary` |
| 状态点 | 9px 圆点 | `state-success/warn/error/idle-primary` |
| 更新时间 / 免责说明 | 11px / 10px | `--dsw-alias-label-secondary` |
| 活动流 kind | 10px，固定 30px 宽 | `--dsw-alias-label-secondary` |
| 活动流文本 | 12px 等宽，单行省略 | `--dsw-alias-label-primary` |
| 游戏说明（标题·得分·最高） | 15px | `--dsw-alias-label-secondary` |
| 键盘提示 | 12px | `--dsw-alias-label-secondary` |
| 按钮（次级） | 14px，圆角 8，描边，内边距 5×14 | `border-l2` / `bg-layer-2` / `label-primary` |
| 分段控件容器 | 外描边 1px、圆角 8、内部分隔线 | `border-l2` / `border-l1` |
| 分段项 | 12px，内边距 2×10，未选中为次要色 | `label-secondary`（选中用 `label-primary` + `bg-layer-2`） |
| 设置标签（纯文本） | 12px，无边框、无内边距 | `label-secondary` |
| 主按钮（浮层） | 12px / 600，薄荷绿底 + 深色字 | 游戏配色（浮层属画面，允许自有颜色） |

**禁止**：卡片嵌套、阴影、10px 以下的正文、第三个并列 pill、居中窄栏、左右分栏。

## 5. 状态与文案

| 状态 | 状态文本 | 更新时间 |
|---|---|---|
| idle | 空闲 · 等待本会话任务 | 有则显示 |
| running（无活动） | 任务开始，Agent 正在规划 | 显示 |
| running（有活动） | 正在执行任务 | 显示 |
| pending_approval | 【重要】等待你审批工具调用！ | 显示 |
| success | 任务执行成功 ✅ | 显示 |
| failed | 任务执行失败 | 显示 |
| aborted | 任务已中断（未知结束原因时显示「本轮已结束（未知原因）」） | 显示 |
| loading（health） | 正在读取监控数据… | — |
| degraded（health） | 监控数据不可用 | — |
| stale（health） | 状态同步中断（可能已断开） | — |

- 显示真实 `stepCount`（「已完成 N 步」），不显示总步数；步数为 0 时省略。
- `health` 是 Client 展示字段，不改变 M0 的六值 `status`；approval / failed 的告警文案优先于 health。
- 告警条：可换行，`【重要】等待你审批工具调用 · 工具 xxx` / `任务执行失败 · <错误摘要>`；不提供任何操作按钮。

### 5.1 任务结束后的「查看对话」入口

- 仅在本轮结束（`success` / `failed` / `aborted`）时，状态行右侧出现一个次级按钮 **「查看对话」**；运行中、空闲时不显示。
- 点击调用 Conversation 视图的 `openView('chat', '')` 切回「对话」标签，只做视图导航：不发送消息、不取消/重试任务、不触碰审批。
- 若宿主未提供 `openView`（能力缺失），按钮不渲染，降级为纯看板。

## 6. 棋盘与游戏操作

### 6.0 游戏切换

- 说明行左侧「贪吃蛇」「五子棋」两个轻量页签，选中态用描边 + 背景区分；切换时**两局都保留**（切到五子棋会自动暂停贪吃蛇）。
- 两个游戏共用同一个棋盘容器与同一行说明；同一时刻只渲染一个画布。

### 6.0.1 游戏设置

- 可点击项一律渲染成**分段控件**（`.wb-seg`：外描边 + 内分隔线的胶囊），不可交互的文字（如「速度」「难度」）是**无边框的纯文本标签**，两者在视觉上必须能一眼区分（决策 D18）。
- 说明行在页签右侧提供当前游戏的设置：
  - 贪吃蛇：`速度` 三档「慢 / 标准 / 快」，决定本局起始节奏与加速步长。
  - 五子棋：`难度` 三档「初级 / 中级 / 高级」，决定电脑的候选范围、防守权重与随机度。
- 设置改动立即保存到浏览器本地存储（键 `dsh-wait-buddy.settings.v1`），刷新后保留；不影响监控数据，也不涉及分数持久化。
- 切换设置在界面上即时生效：贪吃蛇改速度会同时调整当前局节奏；五子棋改难度作用于下一手电脑落子。

### 6.1 贪吃蛇

- 棋盘尺寸由容器实测：`cols = clamp(round(width / 18), 16, 120)`、`rows = max(round(height / 18), 8)`；绘制时 `cellW = width/cols`、`cellH = height/rows`，格子近似正方形。
- 格数在**每局开始时锁定**：resize 只在外层容器变化且当前不是 running/paused 时重新推导；对局中窗口缩放仅拉伸绘制，不改格数。
- 初始蛇 3 节居中，食物随机落在空格。
- 不提供软方向键（决策 D7）。**注意：M0 §5 要求画布内软按钮，D7 与基线冲突，待产品负责人确认；确认前 M1 验收按已知偏离记录。**
- 方向键仅在焦点位于视图内时生效：视图根节点与棋盘容器均为 `tabIndex=0`，点击棋盘即可获得焦点；点击「开始/继续/再来一局」后自动把焦点交还视图。
- 保留「暂停 / 重置」两个普通按钮与浮层主按钮。
- 提示文案固定为「方向键控制，点棋盘后生效」。
- 取舍：触屏或纯鼠标设备无法操控方向，明确接受。

### 6.2 五子棋

- 15×15 交叉点；人执黑先手、电脑执白。电脑为纯前端启发式：先确保自己连五、再堵对方连五，否则按四方向的连子数/开口数加权选点，候选限定在已有棋子周围 2 格内。
- 棋盘为正方面板，边长 = 画布可用高度（上限 520px），水平居中，木质底色 + 网格 + 星位，最后一手用红点标记。
- 交互：点击交叉点落子；连五或满盘时棋盘上浮层显示结果与「再来一局」。
- 说明行：`你 N 手 · 电脑 M 手` +「重新开始」+ 提示「点击交叉点落子」。
- 难度三档：初级（候选半径 1、防守权重 0.35、前 3 点随机）、中级（半径 2、防守 0.9、取最优）、高级（半径 3、防守 1.15、最优并偏好制造双威胁）。三档都会堵对方成五，强弱来自候选范围、防守权重与随机度。
- 不做悔棋、计时、联网（后续迭代）。

### 6.3 M3 联动反馈

- `agent:approval_enter`：贪吃蛇 running 时自动暂停，浮层标题「等待审批」、正文「Agent 等待审批，已自动暂停」；审批未处理前「继续」按钮禁用。
- `agent:approval_leave`：不自动恢复；浮层正文「已处理，按空格或点击继续」，用户点击「继续」或按空格恢复。
- `agent:step_advance`：+5 分，棋盘中央浮字 `+5`，约 1.2 秒淡出，不打断游玩。
- `agent:task_finish` success：+50 分，棋盘顶部 toast「任务完成！+50 分」，约 4 秒淡出。
- `agent:task_finish` failed / aborted：只显示「任务失败」/「任务已中断」toast，不重置、不结束本局；未知原因显示「本轮已结束」。
- 奖励只在游戏非 idle 时生效；奖励不改变 `tickMs`。
- 五子棋不消费暂停/奖励信号（M3 预设只作用于贪吃蛇）。

## 7. 浮层与可访问性

- 贪吃蛇浮层：idle「方向键控制，吃到果实得分」→ 开始游戏；paused「已暂停」→ 继续；manual「已手动暂停，点击继续恢复」→ 继续；session-switch「切换会话后已暂停」→ 继续；view-inactive「视图切换后已暂停」→ 继续；approval「等待审批」→ 继续按钮禁用，且优先于「游戏结束」/「开始游戏」浮层；approval 消失后「已处理，按空格或点击继续」→ 继续；over「游戏结束 + 得分 N」→ 再来一局。浮层不重复游戏标题。
- 暂停浮层使用半透明遮罩（约 48%），保留棋盘/蛇的可辨识度，避免用户误以为进度丢失。
- 五子棋浮层：won「你赢了」/ lost「电脑赢了」/ draw「平局」→ 再来一局（仅终局出现）。
- 棋盘 `role="img"` + `aria-label`（含当前得分）；状态文本 `aria-live="polite"`；告警 `role="alert"`；按钮均有可读标签。
- 视图切走 / 切会话 / 页面隐藏 → 自动暂停并保留进度。
