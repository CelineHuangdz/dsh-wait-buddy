# dsh-wait-buddy 需求基线（M0 定稿）

> **原文标题**：✅ M0 基线正式定稿：dsh-wait-buddy
> **状态**：已冻结（2026-11-05）。
> **插件标识**：`dsh-wait-buddy`
> **视图标签名称**：WaitBuddy
> **定位**：DSH 桌面版会话视图，Agent 长任务陪伴监控面板；监控优先、游戏为辅。
> **核心铁律**：监控告警优先级 > 游戏体验；M1/M2/M3 只做 Agent → 游戏单向信号驱动；不侵入原生审批弹窗。

## 1. 整体定位 & 一句话目标

dsh-wait-buddy：DSH桌面版 · Agent长任务陪伴监控面板（监控优先、游戏为辅）
原则：监控告警优先级 > 游戏体验；单向事件驱动优先；不侵入原生审批弹窗。
用途：长任务等待场景，一边看Agent进度、接收审批提醒，一边轻度小游戏消磨时间；红线：永远不能盖过DSH自带审批弹窗；M1/M2/M3阶段不做反向控制Agent。

## 2. 约束与边界清单

✅ 允许：
1. 监听Agent/会话只读事件：任务启动、step更新、工具调用等待审批、完成、失败、中断
2. 在Session View内渲染进度信息、状态告警UI
3. 嵌入轻量Canvas小游戏
4. Agent事件单向驱动游戏加分、特效、暂停、提示

❌ 基线内禁止（M1/M2/M3都不做，放入备选池）：
1. 游戏操作反向控制Agent（取消任务、自动发送消息、自动审批等）
2. 重型资源、3D类游戏
3. 修改/抢占原生审批弹窗优先级
4. 强行估算精准百分比进度（Agent循环规划，总步数未知）

补充：采用Session View形态，视图天然绑定所属sessionId，天然隔离其他会话事件。

## 3. 用户角色 & 使用场景

用户：DSH桌面版使用者
典型场景：
1. 启动预计耗时较长的Agent任务，为本会话打开WaitBuddy视图；推荐分屏布局：左侧对话视图，右侧WaitBuddy视图。
2. 一边游玩小游戏，同时查看任务状态。
3. 出现等待审批、任务报错等高优先级事件，面板给出醒目辅助提醒，用户处理对应事项。
4. 任务执行完毕，查看联动奖励反馈（M3阶段）。

## 4. 里程碑规划（各阶段独立可交付、可验收）

- M0：需求基线冻结（当前阶段）
- M1：最小可用监控面板，纯状态看板，无游戏，可独立使用
- M2：嵌入贪吃蛇小游戏，游戏与Agent任务完全解耦
- M3：单向联动：Agent事件驱动游戏反馈（Agent → 游戏）
- M4（可选高阶，不在基线强制排期）：双向交互、分数持久化、多游戏切换等，全部放在备选想法池

## 5. 首版小游戏选型

选定：贪吃蛇（M2内置第一款游戏）
特性：Canvas实现、无外部图片资源、打包体积小；键盘方向键控制，画布内附带软按钮，规避WebView键盘捕获冲突；独立状态：分数、暂停、游戏结束、重置；不引入第三方游戏SDK。
备选池预留：2048、消消乐（M4多游戏切换候选）。

## 6. 订阅事件清单

本表为 M1/M2/M3 目标订阅事件集合，是满足基线功能的最小子集。DSH 内核还有其它会话、工具、流式事件，暂不订阅；后续功能迭代需要额外事件时，统一走需求评审，从备选池纳入版本。

| 事件名称 | 触发时机 | 面板展示文案 | 状态颜色 | 告警等级 |
|---|---|---|---|---|
| `session.task.start` | Agent启动一轮任务 | 🟢 任务开始，Agent正在规划 | 绿色 | 普通 |
| `session.step.update` | Agent完成单步（思考/工具调用返回） | 🟡 执行Step N / 总步数未知 | 黄色 | 普通 |
| `session.tool.pending_approval` | 工具调用等待人工审批 | 🔴【重要】等待你审批工具调用！ | 橙红色 | 高告警 |
| `session.task.success` | 本轮任务正常完成 | 🟢 任务执行成功 ✅ | 绿色 | 普通 |
| `session.task.failed` | 任务报错、异常终止 | 🔴 任务执行失败 | 红色 | 高告警 |
| `session.task.abort` | 任务被手动取消/中断 | ⚫ 任务已中断 | 灰色 | 普通 |
| `session.active.change` | 视图切换绑定至新会话 | 切换跟踪到新会话，清空旧任务状态 | — | 状态重置 |

> 进度表达方案：不做0~100%百分比进度；仅展示 stepCount，配合脉冲跳动条（仅表示有新进展，不代表比例）。

## 7. 告警规则（业务规则，视觉动画、配色属于实现细节）

1. 高告警触发条件：收到 `session.tool.pending_approval`、`session.task.failed` 事件
2. 告警定位：本插件告警仅作为辅助二次提醒；DSH 原生审批弹窗拥有最高优先级，插件告警不得拦截、覆盖、替代原生弹窗
3. 告警生效范围：仅对当前视图绑定的会话生效，忽略其他会话产生的告警事件
4. 告警解除条件：对应审批流程完成、任务取消、任务正常结束，告警状态清除

## 8. 前端业务状态模型

```ts
type TrackState = {
  activeSessionId: string | null
  status: 'idle' | 'running' | 'pending_approval' | 'success' | 'failed' | 'aborted'
  stepCount: number
  latestAction: string // 最近动作文本：例如 "调用 dsh-ops 读取文件 xxx.ts"
  isAlerting: boolean
}
```

状态说明：
- idle：空闲（初始、任务结束后回到 idle）
- 触发重置时机：收到任务启动事件、视图切换绑定至新会话时，重置监控状态：`stepCount = 0`，清空 `latestAction`；仅重置监控状态，**贪吃蛇游戏状态独立保留，不会被自动重置**。
- 备注：M3阶段Agent任务给到的游戏奖励，归属当前绑定会话；跨会话切换后，新会话任务的奖励会叠加到当前本局游戏，属于预期行为。

## 9. M3 单向联动规则（Agent → 贪吃蛇）

> 联动信号契约：
> 监控模块职责边界：仅负责订阅DSH内核事件，映射为固定的 `agent:*` 信号集并向外广播；监控层**不定义任何奖励、特效、游戏行为**。
> 联动反馈逻辑归属游戏实现：每款游戏自主实现对信号的响应（加分、刷道具、buff、暂停等）；同一个信号给到不同游戏，可以设计完全不一样的反馈。
> M3基线内贪吃蛇采用预设响应逻辑，这只是贪吃蛇单游戏的默认配置，并非信号契约本身的固定规则。
> 后续修改单款游戏的联动反馈（调整分值、增加buff、更换特效），属于该游戏内部迭代，不改动顶层信号契约、不改动M1监控骨架，不视为基线变更。
> 如果需要新增顶层 `agent:*` 信号类型，需求先进入备选想法池，评审通过后方可纳入版本。

贪吃蛇预设联动行为：
1. `session.step.update`：每完成一步 → 贪吃蛇 +5分，画布短暂弹出浮动文字 `+5`，不打断游戏游玩
2. `session.task.success`：任务成功结束 → 一次性奖励 +50分，弹出提示【任务完成！奖励分数】
3. `session.task.failed / session.task.abort`：弹出提示【任务失败/中断】，不自动重置、不结束本局蛇游戏，保留当前游戏进度
4. `session.tool.pending_approval`（等待审批）：自动暂停本局小游戏，提醒用户优先处理审批；审批处理完毕、告警状态清除后，由用户手动恢复游戏。
> 备注：该暂停行为是插件自定义业务逻辑，DSH 原生审批弹窗本身不会阻塞前端游戏渲染。
